# チケット受付期間の補強調査(1アーティスト集中)

サンドーム福井の以下の公演について、チケットの先行・抽選・一般発売の**受付期間**を調査してください。

{{EVENT_LINES}}

## 手順

「{{ARTIST}} サンドーム福井 チケット」「{{ARTIST}} ツアー チケット 先行 受付期間」等で検索し(4〜5回まで)、
アーティスト公式サイト・ファンクラブ・チケット特設ページ・プレイガイド(ぴあ/イープラス/ローチケ)から受付情報を抽出する。

- **チケット特設ページ(/ticket 等)を見つけたら必ず WebFetch で本文を読む**。期間は一覧ページではなく特設ページに書かれていることが多い
- FC先行・プレリク・オフィシャル先行・一般発売に加え、CD封入シリアル先行・モバイル会員先行など特殊な受付形態も対象
- 受付ページに「予定枚数終了」「販売終了」等の表示があれば `"sold_out": true` を付ける(表示が確認できた場合のみ)
- 受付期間が明記されていれば `+09:00` 付き ISO 8601 で記録。見つからなければ null のまま(推測で日時を作らない)
- confidence: 公式サイト・公式プレイガイド明記 → `official`、二次情報のみ → `inferred`
- `url` には**その受付に申し込めるページ**だけを入れる(プレイガイドのその公演専用ページ、
  または公式のその公演のチケット受付案内ページ)。確認できなければ `null`。
  **転売・リセール仲介(チケジャム等)、まとめサイト、個人ブログ、ニュース記事は入れない**
  (`ticketjam.jp` `ticket-festa.com` のようにドメインに ticket を含むだけの無関係サイトに注意)。
  公式リセール(チケプラTrade 等)は公式の仕組みなので含めてよい

## WebFetch がブロック・失敗した場合の迂回

1. Wayback Machine 経由で再試行する: `https://web.archive.org/web/https://<元のURL>`
2. それでも読めなければ、WebSearch で同じ情報の別ソース(プレイガイドのページ、音楽ニュース記事)を探す
3. どうしても確認できなければ null のままにする(でっち上げない)

## 出力

`{{OUT_FILE}}` に以下の形式で保存(スキーマは collector/schema.json 準拠):

```json
{
  "collected_at": "(実行日時 ISO 8601 +09:00)",
  "events": [
    {
      "title": "(公演の正式名称そのまま)",
      "artist": "{{ARTIST}}",
      "date": "(上記の公演日)",
      "open_time": null, "start_time": null,
      "source_url": "(確認した情報源URL)",
      "tour_url": "(公式サイトのこのツアーのページURL。見つからなければ null)",
      "confidence": "inferred",
      "lotteries": [
        { "name": "(受付名そのまま)", "starts_at": "...", "ends_at": "...", "url": "...", "confidence": "official" }
      ]
    }
  ]
}
```

- 上記の全公演日ぶんの events を出力する(抽選が両日共通なら同じ内容を各日に入れる)
- `tour_url` はアーティスト公式サイト(またはツアー特設サイト)の**このツアーの日程ページ**。
  会場サイト・公式トップページ・プレイガイド・ニュース記事は入れない。見つからなければ null
- 表記は情報源の主たる表記をそのまま使う。独自整形をしない
- 開場・開演時刻も判明したら open_time / start_time に入れる。
  ただし**公演日ごとに個別に確認する**こと(同一ツアーでも土曜と日曜で開場時刻が違うことが多い)。
  他の公演日の時刻を流用せず、その日の値が確認できなければ null にする
- 最終出力はファイル保存のみ。標準出力には見つけた受付の一行サマリだけ述べる
