# サンドーム福井 ライブ情報収集タスク

あなたはサンドーム福井(福井県越前市)のライブ・コンサート情報を収集するエージェントです。
WebSearch / WebFetch を使って以下の手順で調査し、結果を JSON ファイルに保存してください。

## 手順

### 1. 会場起点(確定情報の収集)

- 「サンドーム福井 イベント」「サンドーム福井 イベントカレンダー」等で検索し、会場公式サイト(sundome.jp)のイベント予定を取得する
- **ライブ・コンサートのみ**を対象とする(産業展示会・見本市・式典は除外)
- ここで見つけた公演は `confidence: "official"` とする

### 2. 抽選・先行情報の逆引き(公演ごと)

**手順1・手順3で見つけたすべての公演**について(手順3の発見分も必ずここに通す):

- 「(アーティスト名) ツアー チケット 先行」「(アーティスト名) サンドーム福井 チケット」等で検索する
- アーティスト公式サイト・ファンクラブ・チケットサイト(チケットぴあ / イープラス / ローチケ)のページから、
  FC先行・プレリク先行・オフィシャル先行・一般発売などの**受付期間(開始・終了日時)と申込URL**を抽出する
- `lotteries[].url` には**その受付に申し込めるページ**を入れる。優先順位:
  1. プレイガイドの**その公演専用**ページ(イープラス / ぴあ / ローチケ / チケットボード等)
  2. 公式サイト・FCの**その公演の**チケット受付案内ページ
  3. どちらも確認できなければ `null`(サイトのトップページで埋めない。公演が特定できず役に立たない)
- **転売・リセール仲介(チケジャム / チケット流通センター等)、まとめサイト、個人ブログ、
  ニュースメディアの記事は `url` に絶対に入れない**。踏んでも申し込めず、URLなしより有害。
  ドメイン名に「ticket」が入っているだけの無関係サイトに釣られないこと
  (`ticketjam.jp` `ticket-festa.com` はいずれも申込先ではない)。
  ただし**公式リセール(チケプラTrade 等)は公式の仕組みなので対象に含めてよい**
- CD封入シリアル先行・モバイル会員先行など特殊な受付形態も対象。受付期間が未発表なら
  `starts_at` / `ends_at` は null のまま、名前とURLだけでも記録する
- 受付ページに**「予定枚数終了」「販売終了」「受付終了」等の表示がある場合は `"sold_out": true`** を付ける
  (先着販売は期間内でも在庫切れで終わることがある。表示が確認できた場合のみ付け、推測では付けない)
- **抽選名だけ見つけて期間を書かずに済ませない**。チケット特設ページ(/ticket 等)を見つけたら
  必ず WebFetch で本文を読み、受付期間(開始・終了日時)を探すこと。期間は一覧ページではなく
  特設ページに書かれていることが多い
- WebFetch がブロック・失敗した場合の迂回: ① `https://web.archive.org/web/https://<元のURL>` で再試行
  ② WebSearch で同じ情報の別ソース(プレイガイド・音楽ニュース)を探す ③それでも不明なら null のまま
- 受付期間は情報源に明記されているものだけを記録する。**推測で日時を作らない**
- チケット情報の confidence: 公式サイト・公式プレイガイドに明記 → `official`、まとめサイト等の二次情報のみ → `inferred`

### 3. 未発表公演の逆引き(先行情報の発見)

会場公式カレンダーは直近数ヶ月分しか掲載されないため、**ここが先行キャッチの要**。
実行日の年を Y として、以下のパターンで検索する(発見用検索は合計6回程度まで):

- 「"サンドーム福井" ツアー Y」「"サンドーム福井" ツアー Y+1」「"サンドーム福井" ツアー Y+2」
  (**必ず翌年・翌々年も検索する**。ツアーは半年〜1年以上先まで発表される)
- 「"サンドーム福井" 公演決定」「サンドーム福井 ライブ Y+1」
- 「"サンドーム福井" チケット 先行」

注意点:

- アーティスト公式サイトがティザー(coming soon)状態でも、**公演日と会場が確認できれば含める**
  (開場・開演が未発表なら null、チケット情報が未発表なら `lotteries: []` でよい)
- 見つけた場合は `confidence: "inferred"` として含める(公演日と情報源URLが確認できるもののみ)

## 出力

調査結果を **`collector/out/events.json`** に Write ツールで保存してください。
形式は `collector/schema.json` の JSON Schema に従うこと。要点:

```json
{
  "collected_at": "2026-07-30T03:30:00+09:00",
  "events": [
    {
      "title": "公演名(ツアー名)",
      "artist": "アーティスト名",
      "date": "2026-09-12",
      "open_time": "16:00",
      "start_time": "17:00",
      "source_url": "https://...",
      "artist_url": "https://...",
      "tour_url": "https://...",
      "confidence": "official",
      "lotteries": [
        {
          "name": "FC先行(抽選)",
          "starts_at": "2026-07-01T12:00:00+09:00",
          "ends_at": "2026-07-14T23:59:00+09:00",
          "url": "https://...",
          "confidence": "official"
        }
      ]
    }
  ]
}
```

## ルール

- **表記はすべて情報源の主たる表記をそのまま使う**。「◯◯ コンサート(ツアー名)」のような独自の整形・言い換えをしない
  - `artist`: 公式サイトの正式名義をそのまま(勝手に「from EXILE TRIBE」等を付けたり外したりしない)
  - `title`: ツアー・公演の正式名称をそのまま
  - `lotteries[].name`: 受付ページに書かれている先行名をそのまま
- 日時はすべて日本時間。`starts_at` / `ends_at` は `+09:00` オフセット付き ISO 8601 で書く
- **`open_time` / `start_time` は公演日ごとに個別に確認する**。同一ツアーの連続公演でも
  曜日によって異なることが多い(土曜は開場17:00、日曜は開場16:00 等)。
  **他の公演日の時刻を流用しない**。その日の時刻が確認できなければ `null` にする
  (別の日の値で埋めると、翌日以降の収集で値が揺れて誤った更新通知の原因になる)
- 不明な値は `null`(でっち上げない)。受付期間が全く見つからない公演は `lotteries: []` でよい
- 公演日から6ヶ月以上過去の公演は含めない。今日以降の公演を優先する
- 各イベント・各抽選に必ず情報源の URL を付ける(確認できないものは含めない)
- `artist_url` には**アーティスト公式サイトのトップページURL**を入れる(調査中に必ず訪れるはず)。
  公式サイトが見つからない場合は null。ファンサイト・まとめサイト・SNSは入れない
- `tour_url` には**アーティスト公式サイト(またはツアー特設サイト)の、その公演・ツアーのページURL**を入れる。
  サイト内の「LIVE / TOUR / SCHEDULE」から、このツアーの公演日程・会場一覧が載っているページを探す。
  必ず存在するはずなので、公演ごとに必ず探すこと。ただし以下は `tour_url` ではない:
  - 会場公式サイト(sundome.jp / sundome.sankan.jp)のページ → それは `source_url`
  - 公式サイトのトップページ → それは `artist_url`
  - プレイガイド(ぴあ / イープラス等)の販売ページ → それは `lotteries[].url`
  - ニュース記事・まとめサイト
  探しても見つからなければ null(別の URL で埋めない)
- 検索は必要十分な回数に留める(1公演あたり2〜3回まで)
- 最終出力はファイル保存のみ。標準出力への長文説明は不要(保存した件数の一行サマリだけ述べる)
