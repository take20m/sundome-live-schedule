# メール購読(新着まとめメール) 仕様

2026-10-03 合意。`/subscribe`(新着情報を受け取る)に、メールで新着を受け取る手段を足す。

## 受入条件

1. `/subscribe` でメールアドレスを入れ、届いた確認メールのリンクを押すと購読が始まる
2. 前回送った後に新着(新しく分かった公演、一般で申し込める抽選の受付開始)があれば、毎日 12:00 JST ごろに 1 通のまとめメールが届く。新着がない日は送らない
3. どのメールにも配信停止のリンクがあり、停止するとすぐ止まり、アドレスも消える
4. プライバシーポリシー(/about)に、メールアドレスの扱い(預かるもの・目的・保管と削除・外国の事業者の名前と国とその国の制度・開示等の依頼先)を書き足す

## 非目標

- アーティストごとの絞り込み
- メールへの広告(入れないので、特定電子メール法の住所表示は求められない想定。入れるなら見直す)
- プッシュ通知
- 1 件ごとのメール

## 登録

- フォーム: メールアドレス + Cloudflare Turnstile。サーバー側で Turnstile を検証してから受け付ける
- 受け付けたら確認メールを送る。確認リンクの有効期限は 48 時間
- 応答は登録済みでも未登録でも同じ「確認メールを送りました」(誰が登録しているかを探られないように)
- 購読中のアドレスに再登録があっても確認メールは送り直さない(他人のアドレスで確認メールを乱発させない)
- アドレスは前後の空白を除き、小文字にそろえて保存する。形式が明らかにおかしいものは受け付けない
- 確認待ちのまま 10 分以内に同じアドレスで登録されても、確認メールを送り直さない
- 登録ボタンの下に「登録すると、プライバシーポリシー(メールアドレスの扱い)に同意したものとします」と出す。
  送信の Resend と保存の Cloudflare は米国の事業者なので、外国の第三者への提供として本人の同意を得る(個人情報保護法 28 条)

## 保存(D1)

表 `subscribers`

| 列 | 内容 |
| --- | --- |
| id | 連番 |
| email | 一意 |
| status | `pending`(確認待ち)/ `active`(購読中) |
| confirm_token_hash | 確認リンクのトークンの SHA-256。トークンそのものは保存しない |
| confirm_expires_at | 確認リンクの期限 |
| unsubscribe_token | 配信停止リンクのトークン。毎回のメールに載せるのでそのまま持つ(漏れても、できるのはその人の配信停止だけ) |
| created_at / confirmed_at | 日時 |

- 確認されないまま 7 日たった行は消す(毎日の定期実行のついでに)
- 配信停止したら行ごと消す(停止済みのアドレスを持ち続けない)

表 `digest_state`: 前回まとめメールに入れた最後の `changes.id` を 1 行で持つ

## 送信

- Worker の Cron Trigger(`0 3 * * *` = 12:00 JST)で動かす。毎晩 17:00 JST の収集のあとのデータを使う
- 前回送った `changes.id` より後の新着を、RSS と同じ基準で集める(`listRecentChanges` の会員限定除外と、`groupLotteryChanges` の同じ受付期間のまとめ)
- 新着が 0 件なら送らない。見送った変更(更新・会員限定)を次回また読まないよう、`digest_state` の位置だけは進める
- 購読者が上限を超えて送らなかった日は、`digest_state` を進めない(次回、同じ新着から送れるように)
- Resend のバッチ API(1 回 100 通まで)で 1 人 1 通ずつ送る(配信停止リンクが人ごとに違うため)。`Idempotency-Key` に日付と区切り番号を入れ、再実行で二重に送らない
- 送れたら `digest_state` を今回の最後の id に進める

## メールの中身

- 送信元: `サンドーム福井ライブ情報 <news@sundome.take20m.dev>`、返信先: `contact@take20m.dev`
- 件名の例: 「新着: Vaundy の抽選受付が始まりました ほか2件」
- 本文: 新着の一覧(各公演ページへのリンク)。HTML とテキストの両方
- 末尾: 送信者名、連絡先、このメールを受け取っている理由、配信停止のリンク
- ヘッダー: `List-Unsubscribe`(停止 URL)と `List-Unsubscribe-Post: List-Unsubscribe=One-Click`

## 配信停止

- メールのリンク → `/subscribe/stop?t=<トークン>` のページで「配信を停止する」ボタンを押すと止まる(セキュリティ製品がリンクを自動で開いても止まらないように、GET では止めない)
- メールソフトのワンクリック停止(RFC 8058)は同じ URL への POST で止める

## 上限

- Resend の無料枠は 1 日 100 通・月 3,000 通(2026-10-03 に料金ページで確認)
- 購読者が 90 人を超えたら、その日は送らずにログに残す。有料プラン(月 20 ドル、日の上限なし)に上げるかはその時に決める

## 運営者の作業(コードの外)

1. Resend のアカウントを作り、送信ドメイン `sundome.take20m.dev` を登録して API キーを作る
2. Resend が示す DNS レコード(SPF・DKIM など)を Cloudflare の take20m.dev ゾーンに追加する
3. Cloudflare で Turnstile のウィジェットを作り、サイトキーとシークレットキーを得る
4. `wrangler secret put RESEND_API_KEY` と `wrangler secret put TURNSTILE_SECRET` で登録する(サイトキーは公開値なので wrangler.toml の vars に置く)

## テスト方針

- 登録 → 確認 → 購読中、二重登録、期限切れの確認リンク、配信停止(GET では止まらない、POST で止まる)
- まとめに入る新着の選び方(会員限定の除外、同じ期間のまとめ、前回より後だけ)、新着なしの日は送らない
- Resend と Turnstile への通信はテストでは差し替える

## 公開のしかた

キー(RESEND_API_KEY・TURNSTILE_SECRET・TURNSTILE_SITE_KEY)がそろうまでは、メールの欄・登録 API・プライバシーポリシーの追記を出さない。
Cron Trigger は動くが、RESEND_API_KEY が無ければ何もしない。

## 元に戻すとき

Cron Trigger を外してフォームを隠す。D1 の表は残っても害はない。
