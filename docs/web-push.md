# プッシュ通知(Web Push) 仕様

2026-10-04 合意。`/subscribe`(新着情報を受け取る)に、端末への通知で新着を受け取る手段を足す。
中身と送る時刻はメール購読(docs/email-digest.md)と同じ。

## 受入条件

1. `/subscribe` のいちばん上に「通知で受け取る」の欄を置く。通知を使える端末ではボタンで許可を求めて登録する。
   使えない端末(ホーム画面に追加していない iPhone など)では、ホーム画面に追加する手順へ案内する
2. ホーム画面から開いた人には、トーストを「通知を受け取る」に切り替え、その場で許可を求める(それ以外はメールの案内のまま)
3. 毎日 12:00 JST に、メールと同じ新着を 1 通の通知にまとめて送る。押すと、新着が 1 件ならその公演ページ、複数ならトップを開く
4. 「通知を止める」で登録を消せる。届かなくなった宛先(プッシュサービスが 404/410 を返す)は自動で消す
5. プライバシーポリシーに、保存するもの(端末の宛先)と送る経路(各社のプッシュサービス)を書き足す

## 非目標

- アーティストごとの絞り込み
- 外部の通知サービス(OneSignal など)
- 1 件ごとの通知

## 仕組み

- 送信用の鍵(VAPID, P-256)。公開鍵は wrangler.toml の vars(`VAPID_PUBLIC_KEY`)、秘密鍵は secret(`VAPID_PRIVATE_KEY`)。連絡先は `mailto:contact@take20m.dev`
- 暗号化と署名は npm の `web-push` の `generateRequestDetails` で作り、送信は Worker の fetch で行う(Node の https は使わない)。
  `nodejs_compat` フラグで node:crypto を使う。Workers で動かない場合は Web Crypto で自前実装に切り替える
- 宛先は D1 の `push_subscriptions`(endpoint 一意、p256dh、auth、作成日時、連続失敗回数)。
  受け付けるのは各社のプッシュサービスの宛先だけ(fcm.googleapis.com、web.push.apple.com、*.push.services.mozilla.com、*.notify.windows.com)
- 毎日の処理は新着を 1 回だけ集め、メールと通知の両方に送ってから送信位置(digest_state)を進める。
  メールと通知は別々に登録・停止でき、同じ人かどうかは結びつけない
- 通知の中身: 題「サンドーム福井ライブ情報」、本文「新着: Vaundy の抽選受付の情報が出ました ほか1件」、アイコンはサイトのロゴ。TTL 12 時間
- 失敗: 404/410 は即削除。それ以外の失敗は回数を数え、5 回続いたら削除
- サービスワーカー(sw.js)に push(通知を出す)と notificationclick(ページを開く)を足す

## 上限

- Workers 無料プランは 1 回の処理で外への通信が 50 件まで。メールの送信(数件)と合わせて、通知は 1 日 40 件までにし、
  超えた分はその日は送らずログに残す。登録が 40 件を超えそうになったら有料プラン(月 5 ドル)を検討する

## テスト方針

- 登録 API(宛先の検証・重複・削除)、まとめの通知の中身と送り先、404/410 での削除、上限
- 暗号化は web-push に任せ、テストでは本当に暗号化されたリクエスト(aes128gcm・VAPID ヘッダー)ができることを確かめる
- プッシュサービスへの通信はテストでは差し替える

## 元に戻すとき

`VAPID_PUBLIC_KEY` を消せば欄とトーストの切り替えが消え、送信もしない。D1 の表は残っても害はない。
